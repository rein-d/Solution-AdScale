# Стратегия данных AdScale

## 1. Тип базы по сервисам

| Сервис | Тип | Обоснование |
|---|---|---|
| Сервис ставок | PostgreSQL + Redis | PostgreSQL держит версии политик, релизы и аудит: релиз применяется транзакционно, откат — это новая версия. Запись — единицы операций в секунду. В аукционе БД не читается, горячие счётчики (pacing, frequency cap, резерв) живут в Redis и пересчитываются при его потере. |
| Сервис кампаний | PostgreSQL | Источник истины для кампаний, бюджетов и таргетинга: CRUD и правки бюджетов идут транзакционно, версию потребляют Bidding и кабинет. 20–200 RPS, объём до 1 ТБ; чтение снимают реплики и кеш, шардирование пока не нужно. |
| Сервис статистики | ClickHouse | 12–33 тыс. событий в секунду, до 3 млрд строк в сутки, запись батчами из Kafka плюс минутные агрегаты. PostgreSQL с таким потоком не справится и снова отоберёт ресурсы у выдачи. |
| Сервис аналитики | ClickHouse (read-контур) + S3 | Отчёты сканируют миллиарды строк, и read replica PostgreSQL тут не помогает — скан остаётся построчным. Отдельный контур держит тяжёлые запросы подальше от OLTP, старая история лежит в S3 Parquet. |
| Сервис финансов | PostgreSQL | Ledger, баланс и счета требуют ACID, идемпотентных списаний и RPO 0 с синхронной репликой в AZ и DR. Баланс для списания берём только из primary, реплика идёт в кабинет с пометкой «на момент». |

## 2. Что важно уточнить

Пер-импрессионная дедупликация и детализация по показам живут в ClickHouse; в финансовый PostgreSQL пишем батчами по 15-минутным окнам — около миллиарда одиночных вставок в сутки OLTP не выдержит.

Креативы и статика отдаются из S3 через CDN, долгая история событий — S3 Parquet, счета и архив ledger — S3 Object Lock. Это архив и раздача байтов, а не замена БД. Ключи шардирования, TTL и топологию реплик не повторяем — они в [scaling.md](scaling.md) и [caching.md](caching.md).

## 3. RPO, бэкапы, конфигурация

| Контур | RPO | Восстановление |
|---|---|---|
| Конфиг ставок, кампании, финансы | 0 | Синхронная реплика, PITR; для денег ещё и DR, RTO ≤ 15 мин (цель 5 мин) |
| Статистика, аналитика | до 5 мин | Replay из Kafka и S3, пересборка витрин |
| Redis | до ~30 с | Пересчёт из ledger и снапшота |

Бэкапы PostgreSQL — base backup плюс WAL, ClickHouse — снапшоты, архив — S3 с версионированием. Восстановление проверяем учениями раз в квартал, а не только на бумаге. Сырые события живут в Kafka 7 дней, дальше уходят в S3; аудит политик ставок — 12 месяцев. Адреса, учётки и секреты приходят извне через переменные окружения, миграции накатываются отдельным шагом — образ остаётся одинаковым для всех сред.
